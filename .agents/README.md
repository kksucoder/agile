## 路由与维护约束

先按任务进入上表所选来源。通用读取顺序为：实际生效的 Agent 指令入口 → 本文件 → 已启用能力的 README 或既有任务来源 → 本次涉及的 Note、Plan、Tasks 和具体证据 → 按需读取被引用的历史资料。同一上下文中规则未变化时不必反复读取，不默认加载整棵文档目录。独立规划文件按用户指定位置、名称和已有格式读取，不因缺少本入口补建 `.agents`。
适用边界按四种模式处理：首次初始化只注入明确启用的能力；已有体系接入只增加最小引用并保留项目定制和状态；显式迁移必须有用户授权并在核对引用后迁移；独立规划只维护用户指定文件，不创建受管理 Work、固定目录、配套 Tasks 或归档结构。本文件只负责发现和路由，不复制能力契约或任务状态。

重要设计变化同步相关决策，进度只更新选定的任务来源。Notes 保存 What/Why 与长期约束，计划保存实施范围与验收，任务保存依赖、状态和证据。不得复制维护同一事实。没有持久化来源的小工作可在交付说明中报告修改与验证，不为填满路由而建档。

代码、需求、决策或计划冲突时，判断实现偏离、文档过时或决策改变；不能把代码现状自动当成正确决定，也不能为同步而抹去原约束。归档仅用于历史追溯，不作为当前架构依据或待执行清单。

只要求规划时不自动开发；独立规划按用户指定位置、名称和格式交付，不要求初始化本入口；已授权实施时按依赖推进，不因生成文档增加确认。本文由项目实际使用的 Agent 入口引用，不假定任一工具自动发现此文件。

## 本文件维护规则

本入口使用 UTF-8 Markdown，首行为唯一的一级标题，随后空行；不设置 Status、Decision state 或 YAML frontmatter。正文依次为来源表、路由与维护约束、本文件维护规则；后二者使用同名二级标题，各一次，不省略。本文件规则属于项目资产，接入后保留，只有初始化注释需要删除。

来源表固定两列“信息”“实际来源”，保留五种信息各一行：重要决策、理由与长期约束；实施计划、任务依赖与进度；预期行为；当前实现；验证事实。每项给出真实来源或明确的未启用、未指定及定位方式，不留空值，不用不存在的链接占位。可追加项目特有来源，但不得为同一事实指定两个独立维护位置。

路由与维护约束必须保留按需读取、单一事实来源、冲突处理、归档仅作历史、规划与实施授权边界及实际 Agent 入口接入说明。可按项目调整措辞，不复制 Notes 或 Work 的格式契约。本入口没有状态转换；接入检查确认来源可定位、链接有效、没有初始化提示及 Skill 安装路径。违规报告文件与对应行或来源项，未完成入口接入如实说明。
